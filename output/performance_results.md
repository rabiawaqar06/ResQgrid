# Performance results

Measured on 2026-11-26 with the **Release** build (MSVC 19.51, `/O2`), Windows 10, Intel(R) Core(TM) i5-6300U CPU @ 2.40GHz.
Files generated by `tools/gen_scenario <locations> 2026 data/perf/perf_<n>.txt 600` and run with `resqgrid <file> --quiet`.
"Sim time" is the time spent inside `Simulation::step()` (the `execution time` statistic, loading excluded).
Each file was run 3 times; the table shows the median run and all three times. Runs stop early once every request is finished.

## What the numbers show

- Each time the size doubles (locations, roads, robots, requests and events all double),
  the simulation time grows about 4x: 3.46 -> 13.9 -> 57.2 -> 221 ms (x4.0, x4.1, x3.9).
- That matches the analysis: the number of Dijkstra runs grows linearly with the number of
  requests (78 -> 1401, about 1.1 runs per request), and each run costs O((V + E) log V)
  with the binary MinHeap, so the total is roughly O(Q * (V + E) log V), about quadratic in size here.
- Even the 1000-location file (2087 roads, 200 robots, 1250 requests) needs only
  about 0.6 ms per step, so the per-step work stays fast as V, E, R and Q grow.
